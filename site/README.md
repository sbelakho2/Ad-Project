# Apex marketing site

Static marketing site for Apex, the no-SDK autopilot for AppLovin MAX, LevelPlay and AdMob. Built with [Zola](https://www.getzola.org/) 0.19.x.

## Build

```
zola build
```

The build writes the site to `public/`. To preview locally with live reload:

```
zola serve
```

## Deploy

`base_url` in `config.toml` is set to `https://apexmediation.ee`, the site's canonical example domain. A production deploy replaces it with the live domain, and the `Sitemap:` line in `static/robots.txt` must be updated to the same domain at the same time.

## Measurement notes

Lighthouse runs under CPU emulation on a developer machine read several points
below native scores for the same bytes. The CI lane audits one page per job on
native hardware, so that lane is the arbiter for the performance budget.

## Layout

- `config.toml`: Zola configuration: `base_url`, title, description, `generate_sitemap = true`, `minify_html = true`, and the `[extra]` navigation, footer and contact data used by the templates.

- `content/`: every page in Markdown with TOML front matter. Marketing: home (`_index.md`), `how-it-works.md`, `pricing.md`, `proof.md`, `security.md`, `for-publishers.md`, `free-audit.md`, `support.md`, `privacy.md`, `terms.md`. Docs: `guides/_index.md` plus the five guide articles, and `guides/api/` (an index page and one page per endpoint).

- `templates/`: `base.html` (header, footer, skip link), `macros.html` (per-page title/description/canonical/Open Graph head block), `index.html` (home), `page.html` (marketing pages: hero plus section blocks), `guides.html`, `guide.html`, `api-section.html`, `api.html`, `404.html`, `shortcodes/lead_form.html` and `sitemap.xml` (the sitemap is also generated by Zola's built-in handling via `generate_sitemap`).

- `static/`: `style.css` (single stylesheet, no framework; the built stylesheets must stay within the 12,000-byte site budget) and `robots.txt`.

- `claims.json`: the claim register described below.

### Free-audit form contract

`free-audit.md` renders the form through `{{ lead_form() }}` (file `templates/shortcodes/lead_form.html`). The form posts to `/free-audit`; Caddy routes the POST to `apex-api`, which validates and answers with a 303 redirect on success or re-renders this page with per-field errors. Field names and ids match: `email` (`type=email`, required), `studio` (required), `platforms` (checkboxes, values `max`, `levelplay`, `admob`, at least one required server-side), `revenue` (optional select) and `notes` (optional, `maxlength=2000`). The error re-render can link each message to `#email`, `#studio`, `#platforms`, `#revenue` or `#notes`.

### Editorial notes that are not published

The privacy and terms pages publish only the finished copy. The design document's two editorial notes are intentionally kept out of the built pages and live here instead:

- Before publication (privacy): add the actual contracting entity, address, data-controller details, processor list, locations, retention schedule and applicable rights process. These are operational facts absent from current implementation, not design decisions. Do not publish invented values.
- Publication status (privacy and terms): these two pages are complete design drafts for the known product facts. The contracting entity must supply the remaining legal and operating particulars before launch. Keep that editorial instruction out of the published page.

## Fonts and artwork

Fonts and images are committed artifacts: the site self-hosts every font
(latin subset WOFF2 under `static/fonts/`) and never fetches fonts or images
from a third party at runtime. Templates reference `/fonts/*.woff2` and
`/logo-mark.svg` directly.

Regenerate the fonts (run the commands in this section from the repository
root; `TMP` is any scratch directory):

```
curl -fsSL -o "$TMP/Manrope[wght].ttf" https://raw.githubusercontent.com/google/fonts/main/ofl/manrope/Manrope%5Bwght%5D.ttf
curl -fsSL -o "$TMP/IBMPlexMono-Regular.ttf" https://raw.githubusercontent.com/google/fonts/main/ofl/ibmplexmono/IBMPlexMono-Regular.ttf
curl -fsSL -o "$TMP/IBMPlexMono-Medium.ttf" https://raw.githubusercontent.com/google/fonts/main/ofl/ibmplexmono/IBMPlexMono-Medium.ttf
curl -fsSL -o "$TMP/IBMPlexMono-SemiBold.ttf" https://raw.githubusercontent.com/google/fonts/main/ofl/ibmplexmono/IBMPlexMono-SemiBold.ttf
python3 -m fontTools.varLib.instancer "$TMP/Manrope[wght].ttf" wght=400 -o "$TMP/Manrope-400.ttf"   # also 700 and 800
UNIS='U+0000-00FF,U+0131,U+0152-0153,U+02BB-02BC,U+02C6,U+02DA,U+02DC,U+2000-206F,U+2074,U+20AC,U+2122,U+2191,U+2193,U+2212,U+2215,U+FEFF,U+FFFD'
pyftsubset "$TMP/Manrope-400.ttf" --flavor=woff2 --unicodes="$UNIS" --layout-features='*' --output-file=site/static/fonts/manrope-400.woff2
```

The same `pyftsubset` line produces `manrope-700.woff2`, `manrope-800.woff2`
and, without the instancer step, `ibm-plex-mono-400.woff2`,
`ibm-plex-mono-500.woff2` and `ibm-plex-mono-600.woff2` from the matching IBM
Plex Mono TTFs. Each committed file starts with the `wOF2` signature and stays
well under 60 KB.

Regenerate the raster icons, lockups and `favicon.ico` from the SVG masters
(needs python3 with Pillow):

```
python3 tools/brand/render_assets.py
```

Regenerate the nine Open Graph PNGs (needs node with npx; the first run
downloads the Playwright package and its Chromium build into the local caches;
set `PLAYWRIGHT_VERSION` to pin a release, default 1.63.0):

```
tools/brand/render-og.sh
```

Both scripts are idempotent and overwrite their outputs in place.
`tools/brand/render-og.sh` renders `og/template.html`, the committed 1200x630
card template, through headless Chromium with the local font files.

## Claim register

Every factual claim about Apex's own behavior that a test could check is anchored in `claims.json`. Each entry has:

- `id`: stable identifier,

- `claim`: the sentence (or fragment) exactly as it appears in the site content,

- `anchor`: the repository path that implements the behavior,

- `test`: the test, or gate, that pins the behavior; when the test lives in a crate's `tests.rs` next to the anchored source file, the file is named in parentheses.

Marketing copy must not make a behavioral claim that is absent from this register, and the register must not cite an anchor or test that does not exist. The site ships zero JavaScript: neither templates nor content contain script tags.
